# Nokhchi Redesign — SwiftUI, iOS 17+

Нативный интерактивный прототип с четырьмя вкладками, MapKit и локальными данными.
Проект: **Nokhchi.xcodeproj**, shared scheme: **Nokhchi**. Внешних зависимостей приложения нет.
По умолчанию включена тёмная тема; светлая и системная выбираются в профиле.

**Статус:** Release для iPhone успешно собран в GitHub Actions на macOS с Xcode 26.3
и iOS SDK 26.2. Создан `Nokhchi-unsigned.ipa` для последующей подписи при установке.
Форматтер и линтер прошли. Задача симулятора отменена по просьбе владельца;
XCTest/XCUITest и визуальная проверка не завершены. Скриншотов нового приложения нет.

Репозиторий: [nokhchi-ios](https://github.com/movsarusumov172-crypto/nokhchi-ios).
[Лог Release-сборки](https://github.com/movsarusumov172-crypto/nokhchi-ios/actions/runs/43838960638).
Общий workflow помечен отменённым: задача **Release for iPhone** завершилась успешно,
оставшаяся задача симулятора была остановлена. Новые запуски выполняются только вручную.

## Открыть и установить на iPhone

1. Перенесите папку проекта на Mac с актуальным Xcode и установленным iOS SDK.
2. Откройте `Nokhchi.xcodeproj`, выберите схему `Nokhchi`.
3. В **Signing & Capabilities** у target `Nokhchi` выберите свою Team.
   При необходимости замените `com.movsar.NokhchiRedesign` на уникальный Bundle Identifier.
4. Для первого запуска выберите доступный iPhone Simulator и нажмите Run.
5. Подключите iPhone, подтвердите доверие и включите Developer Mode, если iOS потребует.
   Выберите подключённый iPhone и нажмите Run. Подпись настраивается вашей учётной записью.

## Release и IPA

Собранный в Actions `Nokhchi-unsigned.ipa` не подписан сертификатом разработчика.
Для установки его нужно подписать своей учётной записью, например средствами Sideloadly,
либо собрать и подписать приложение в Xcode. В Actions нет сертификатов Apple.
Файл доступен в артефакте `Nokhchi-unsigned-ipa` указанного запуска.
Перед загрузкой следующего запуска Actions учитывайте настройки видимости и расход минут.

В Xcode выберите физический iPhone или **Any iOS Device (arm64)** → **Product → Archive**.
В Organizer выполните **Distribute App** и выберите доступный вашему аккаунту способ
распространения. Для IPA нужна действующая подпись и подходящий provisioning profile.
Неподписанный файл `.ipa` не является готовым устанавливаемым приложением.

Для автоматизации подготовлен `scripts/archive.sh`. `ExportOptions.plist` берите из
экспорта Xcode для вашей команды и способа распространения: универсальный файл
подписи с фиктивным Team ID намеренно не включён.

```bash
DEVELOPMENT_TEAM=YOUR_TEAM_ID \
EXPORT_OPTIONS=/absolute/path/ExportOptions.plist \
bash scripts/archive.sh
```

Результат успешного экспорта появится в `build/export/`.
Порядок подписи и распространения описан в
[документации Apple](https://developer.apple.com/documentation/xcode/distributing-your-app-for-beta-testing-and-releases).
Подписанный архив и этот путь экспорта не выполнялись; существующий IPA упакован
из реально скомпилированного Release-приложения без подписи.

## Проверки на Mac

Используется встроенный в актуальный Xcode `swift-format` как форматтер и линтер;
конфигурация `.swift-format` задаёт 100 символов и отступ 4 пробела.
Первую проверку формата выполните до сборки. При необходимости примените форматтер
только к файлам этого нового проекта и повторите проверку.

```bash
xcrun swift-format format --in-place --recursive Nokhchi NokhchiTests NokhchiUITests
xcrun swift-format lint --strict --recursive Nokhchi NokhchiTests NokhchiUITests
xcrun simctl list devices available
bash scripts/verify-mac.sh 'platform=iOS Simulator,name=iPhone 16'
```

Замените имя симулятора на реально установленное. `verify-mac.sh` запускает линтер,
XCTest/XCUITest и Release-компиляцию для физического устройства без подписи.
Результат тестов: `build/Tests.xcresult`; UI-тест прикладывает снимки основных экранов.
Перед повторным запуском выберите новый путь результата или переместите предыдущий
`Tests.xcresult`: Xcode не перезаписывает существующий result bundle.
Для тестов предпочтителен отдельный симулятор: UI-тест взаимодействует с локальным профилем.

## Реализованные сценарии в исходном коде

- Четыре нативные вкладки с независимыми NavigationStack.
- Перемещение/масштаб карты, начальный Гудермес, категории, компас, геолокация
  с запросом разрешения и обработкой отказа, переход ко всем доступным точкам.
- Открытие организаций с карты и из списка, кнопка избранного, открытие города в Apple Maps.
- Поиск без учёта регистра по названию, городу и категории; сортировка; фильтры города
  и избранного; сброс; состояние пустой выдачи.
- Выбор одной из 13 читаемых категорий, haptics, доступная кнопка «Далее».
- Создание/редактирование/удаление черновиков с валидацией и подтверждением удаления,
  ручная точка на карте, защита от случайного закрытия изменённой формы.
- Профиль, редактирование имени, избранное, «Мои бизнесы», настройки и VIP-экран.
- Сохранение темы, имени, избранного, локальной настройки уведомлений и черновиков в JSON.
  Ошибка чтения не приводит к тихой перезаписи повреждённого файла.
- Dynamic Type, одноколоночная сетка при accessibility-размерах, системные кнопки,
  списки, back navigation, safe areas, sheet, confirmationDialog и SF Symbols.

Release-компиляция подтверждена Actions. Этот перечень **не означает пройденных
runtime-тестов**: они были отменены до завершения.

## Демонстрационные ограничения

Пять организаций перенесены из снимков. Рейтинги — исторические значения снимков.
Маркеры организаций обозначают **центр города**, а не адрес; у ПВЗ координат нет.
В Гудермесе показан бизнес со снимка; можно добавить собственный черновик с точкой.
Карта и Apple Maps используют сеть Apple; локальный каталог и формы работают без сервера.

Уведомления сохраняют только предпочтение — push не подключён. Сообщения, VIP-покупки,
подписки, серверный аккаунт, поддержка, публикация организаций и юридические документы
показывают честное описание недоступности. Серверные операции не имитируются.
По дополнительным снимкам реализованы семь этапов: категория, информация, фото, видео,
адрес, часы работы и предпросмотр. Сохранение остаётся локальным; серверная модерация
не подключена. Черновики не смешиваются с каталогом подтверждённых снимком записей.

Данные находятся в Documents/Nokhchi/local-state.json в контейнере приложения;
их можно скопировать через Files или File Sharing. При удалении приложения локальные
данные теряются. Экран восстановления повреждённых данных не реализован; исходный
файл сохраняется, запись блокируется, инструкция показана пользователю.

## Структура

- `Nokhchi/Models` — категории, каталог, фильтрация и валидация черновиков.
- `Nokhchi/Store` — Observable-хранилище с атомарной записью и CoreLocation.
- `Nokhchi/Views` — отдельные экраны и повторяющиеся компоненты.
- `Nokhchi/Resources` — JSON, фотографии, иконка приложения, privacy manifest.
- `NokhchiTests`, `NokhchiUITests` — подготовленные тесты логики, хранения и навигации.
- `docs/SCREENSHOT-ANALYSIS.md` — разбор всех исходных изображений и границ данных.
- `docs/VALIDATION.md` — фактические результаты проверок и ручной чек-лист.

## Сторонние ресурсы

SwiftUI, MapKit, CoreLocation и SF Symbols — системные средства Apple, без стороннего
набора иконок и UI-библиотек. Применяется запрошенное в ТЗ исключение для SF Symbols.
Фотографии — фрагменты пользовательского фото 2; их права отдельно не проверялись,
для публичного распространения понадобятся права на исходные фотографии.
Иконка приложения — простая исходная буквенная геометрия N, без эффектов.
Изображения интерфейсов App Store и Apple Account в ресурсы не включены.
